Sample Source pts + target (1)                      Source / Target pairs (2)

Each point is sampled into a cluster numbered 0-7 at random, with each cluster placed at an angle 2𝛑k/8 around the center. To build the pairs, I paired the source and target samples at random. Using the convention that time 0 is noise and time 1 is data (above equation), I ended up with the velocity vectors at a time from [0, 1]. The second figure shows this using 40 pairs.

The reason that each path’s velocity is constant is that the formula moves each point an equal distance in each equal unit of time (and always in the same direction) so its velocity (x1 - x0) stays the same across the entire path. The [Gaussian] cluster centers are 2.5 units away from the center of the graph, with a Gaussian spread of 0.2 around each center. The source is a Gaussian distribution with spread 1, in the same coordinates.

Task 2 - Implement and train the Velocity Model

Part 1 Training Loss (3)

        My velocity model is a network that takes the points coordinates and the time (x, y, t) as inputs and outputs a 2-dimensional velocity (vx, vy). I used a SiLU neural network in PyTorch that had 3 hidden layers with width 128, which trained 33794 parameters over 20,000 steps. The batch size was 256, which took around 22.3s with my hardware.  

        The network predicts the velocity a point should have at its current position without knowing where the point is going (the point’s endpoint). Whenever generated, it only knows the point’s location and what time it is. The loss ends up dropping quickly and remaining relatively stable (around 4.7) for the duration of the training. The loss can never reach zero because the pairs are random. The model can only predict the average velocity at each point, and the remaining loss reflects how spread out the true velocities are around that average, so it converges around ~4.7.

Task 1 - Choose a Creative Target

Target Shape (S) with mask and samples (7)                       Generated S (100 Euler Steps) (8)

        For Part 2, I chose the letter ‘S’ as the target, which was drawn with Matplotlib’s font onto an image and converted into a binary mask, where ‘true’ marks a pixel inside the letter. To sample a target point, I picked one of the letter’s pixels at random and added a random offset inside that pixel, which spreads the points evenly over the whole letter rather than stacking on top of each other and generating nonsense. No external image was used and the Matplotlib font is under a free license.

        I trained the same network architecture that I used in part 1 for 30,000 steps, which took around ~35.7 seconds (13.4 seconds longer than Part 1). The loss levelled out at around 3.7 (1 point lower than in Part 1). I think the reason that the loss is much less is because my shape in Part 1 was rather abnormal, whereas an ‘S’ is somewhat uniform and much more clustered (not ‘nodal’). Just like in Part 1, the loss doesn’t approach 0 because of the random pairing used in training. Task 3 - Investigating the sample trade-off

Final point clouds for different number of Euler Steps (12)

Quality (left) and sampling time (right) vs number of Euler steps (13)

        With the trained weights and one fixed set of 20,000 Gaussian starting points, I ran Euler sampling with 1, 2, 5, 10, 25, 50, and 100 steps. Sampling time covers only the network evaluations and Euler updates. The number of network evaluations equals the number of steps.

        To measure ‘quality,’ I compared the distributions rather than the individual points. I counted the fraction of points in each square of a 40x40 grid, plus one extra bin for points outside the grid, and computed the total variation distance between the generated and target histograms (0 = identical, 1 = completely different). The target comparison uses another independent sample of 20,000 points. The total variation ended up giving TV = 0.074, while the raw starting noise was TV = 0.526, and a very accurate 500-step solve of the same network gives TV = 0.113.

        Sampling time grows pretty much in proportion to the number of steps, about 3.7 ms per step, because each step is just one network evaluation. At a single step, all the points resulted in one small blob (TV = 0.967). At t = 0 a point is pure noise, so the best direction that the network can predict is the direction towards the average target position. One full-size step, then, just ends up sending every point to the same average point (which creates the blob). With 2-10 steps the S appears but is very blurry. By 25 steps, the quality stops improving as the TV stagnates at around 0.110 from step 25 to step 100.

        The TV against the 500-step solve keeps decreasing, but eventually goes away with more steps. The TV against the real target stays near that same 0.110, meaning that the small network leaned towards a ‘too smooth’ model of the S, trapping some of the points as outliers which are relatively very far away from the boundaries of the S.
