Function to Divide Image into Patches.

Roles of Patch Projection, Positional Embeddings, and the CLS Token:

        Patch Projection is the method by which a vision transformer converts images into tokens. A vision transformer model doesn’t directly understand pixel significance, so images are spliced into sections (‘tokens’) so that the transformer can characterize and quantify the equivalent word embeddings of the selected tokens.

        “Positional Embeddings” refers to the way that the model quantifies each patch’s positional relation compared to other patches in the image. Each patch is assigned a vector by the model so that each token carries information about where the patch came from in the image. Without this embedding, the overall image completely loses context (an eyebrow shouldn’t be below an eye) in a way which prevents the model from accurately predicting contextual understanding.

        The CLS token is an extra vector added to the end of each image’s sequence (ex. 196 + 1). This token carries the prediction of the model in a single place, and is where the singular predicted value of an image class is stored (i.e. German shepherd (0.88)).

        

My patch visualization vs. vit_b_16’s learned patch projection:

        My patch function only rearranges pixels into 196 tiles and does no learning. The model’s patch projection is a layer within the transformer that converts each image into a high-dimensional vector mapping, which is what the model actually uses to predict token information.

Fixed Output Limitation:

        The model’s output layer has ‘only’ 1000 categories, so any image examples which are outside of these 1000 classes will immediately be mislabelled. The model is forced to classify each image, so mislabelling is an inevitability. These images which sit outside the output layer might be easily identified by poor classification scores, like the three above unsuccessful examples. The model is essentially matching an image’s makeup to a label; if the actual label doesn’t exist in the model’s output layer, the classification is incorrect, which is why models with higher categorical libraries always perform better at image classification.

Comparison of computed logits with the model’s built-in output:

        Cosine similarity is the dot product of two vectors, which measures the relationship or similarity between image and text embeddings. A higher cosine similarity generally signals that an image and its related textual embedding or description are closely related, and therefore that CLIPs textual output is correct.

        Logits are those cosines which are multiplied in order to widen the gap (i.e. 0.284 -> 28.4) and further stratify the model’s cosine scores, which allows for a more fine-tuned output. The ordering of the scores is kept, but this prepares the scores for softmax-ing.

        The softmax function converts the raw logits into a probability distribution, so that all probabilities add up to 1 are probabilities which are closer to 1 are more likely to be a correct textual embedding of the image.

Dependence on comparison texts being compared:

        Softmax divides by the sum of all candidates, so it doesn’t necessarily say whether a text embedding is true, just that it is more likely. Every text embedding is scored relative to other embeddings, so that a softmax score is just a probability that a candidate is more likely than another. In the demonstration with ‘tiger_1.jpg,’ the softmax scoring dropped from 0.9999 for tiger to 0.4378 once a distractor ‘tiger cat’ was added. A single candidate was able to drop the probability by that much even though the logit score / cosine similarity remained the same.

Why changing a prompt differs from fine-tuning:

        Changing a prompt changes only the text going into the text encoder, where fine-tuning updates weights based on labeled data, which permanently changes how the model connects inputs to embeddings (this is how the model ‘learns’).

Comparison of results with Part 1:

CLIP was able to correctly classify 20/20 images, while ViT was only able to correctly classify 13/20. ImageNet’s method of classification is based on labelled data, whereas CLIP was trained using image-text scrapers to collect image-text pairs. The ViT chose only among 1000 classes, while CLIP was basically given a five-way choice, making it so that the probability of being wrong was much lower. The poor ViT scoring for german_shepherd makes sense, as two of the images were low-quality, but the poor performance of ViT when identifying tarantulas is surprising.
